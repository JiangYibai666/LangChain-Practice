# 📝 采购订单（PO）

## 采购订单定义  
### 采购订单（PO）  
- **采购订单（Purchase Order，简称PO）**是一种具有法律约束力的合同，用于向供应商购买商品。  
- 通过采购订单，买方可以在收到商品后再付款，而不是像个人购买那样先付款后收货。  

## 采购订单的付款特点  
- 买方根据合同约定，在特定时间内付款（例如月底或公司设定的其他日期）。  
- 采购订单确保买方会在约定时间内支付款项。  

# ⚙️ 采购订单的流程

## 采购订单的发起流程  
- 采购订单通常在发送给供应商之前，需要经过一系列的内部流程。  
- 该流程通常从**PPR（采购需求申请）**开始。  

> **重要提示：**采购订单不仅是购买凭证，更是确保付款和收货流程规范的重要合同文件。

### 采购团队的作用  
- 作为各部门与供应商之间的桥梁  
- 统一管理和协调采购需求  
- 确保采购流程规范和高效  

> **采购流程因公司而异，但基本流程大致相同。**



# 🛒 采购流程

## 采购请求的提出  
### 详细步骤  
- 申请人（如工程师）提出采购需求  
- 例如：“我想购买五个工具”  
- 申请人登录系统（Docsa）  
- 输入采购物品信息  
  - 物品名称  
  - 数量  
  - 规格等详细要求  
- 系统将采购请求发送给采购团队  

## 采购审批流程  
### 详细步骤  
- 采购团队收到采购请求  
- 采购员审核采购请求  
  - 判断是否符合采购条件  
  - 是否使用公司资金购买  
- 采购员批准后，进入下一流程  
- 需要创建正式的**采购申请单**（Purchase Requisition）  

> **采购流程关键点**：  
> 采购请求必须经过系统录入和采购员审批，确保资金合理使用和采购合规。

|--------------|----------|----------------------------|------------------|

| 采购请求审核     | 采购员     | 审核采购请求，决定是否批准采购         | 判断是否使用公司资金购买       |

# 🛒 采购流程

## 采购申请与审批  
### 采购申请提交  
- 采购申请单会发送给相关经理进行审批  
- 经理审批内容包括是否允许从指定供应商购买该物品  

### 价格信息来源  
- 通常已有物品价格目录（**catalog模块**）  
- 目录由采购人员自行填写维护  

## 询价与采购订单  
### 询价流程（RFQ）  
- 当没有现成价格目录或不确定供应商时，启动**询价请求（Request for Quotation, RFQ）**  
- 询价请求发送给多个供应商  
- 供应商返回报价  

### 供应商选择  
- 采购人员根据报价选择最佳供应商  
- 选择标准包括**价格最优**和**交易条件最佳**  

### 采购订单发出  
- 确定供应商和价格后，发出采购订单（PO）  
- 采购订单即为与供应商签订的购买合同  

| 流程阶段       | 主要内容                             | 备注                     |
|--------------|--------------------------------|------------------------|
| 采购申请       | 提交申请，经理审批                     | 是否允许从指定供应商采购         |
| 价格目录       | 使用已有价格目录或自行维护                 | 目录模块由采购人员填写维护         |
| 询价请求（RFQ） | 发送询价请求给多个供应商                  | 当无价格目录或不确定供应商时使用     |
| 供应商选择     | 根据报价选择最佳供应商                    | 价格和交易条件为主要考虑因素        |
| 采购订单       | 发出采购订单，签订购买合同                  | 确认供应商和价格后执行采购          |

> **采购流程核心**：通过审批、询价、选择供应商和发出采购订单，确保采购的合理性和经济性。

# 📦 货物接收与验收流程

## 货物接收流程  
### 详细步骤  
- 先收到所有订购的货物  
- 例如：订购10件商品，供应商送齐10件  
- 初步确认货物数量无误，整体流程顺利  

## 货物验收与质量控制  
### 验收标准  
- 对收到的货物进行质量检查  
- 发现部分商品不符合标准时进行拒收  
- 例如：10件中只有8件合格，2件不合格被拒收  

### 拒收处理  
- 需要货物接收单（**goods receipt**）作为凭证  
- 通过接收单告知供应商合格与不合格的数量  
- 不合格商品可能需要退回供应商  
- 退回流程不属于Docsa管理范围  

### 后续补货  
- 被拒收的商品退回后，供应商可重新发货  
- 重新发货的目的是完成整个订单的交付  

| 流程阶段 | 说明 | 备注 |
| -------- | ---- | ---- |
| 货物接收 | 收到全部订购商品 | 例：10件全部送达 |
| 质量验收 | 检查商品是否符合标准 | 例：8件合格，2件不合格 |
| 拒收处理 | 拒收不合格商品并通知供应商 | 需货物接收单作为凭证 |
| 退货与补货 | 不合格商品退回，供应商补发 | 退货不在Docsa范围内 |

> **重要提示：** 货物接收单是确认商品合格与否的关键凭证，确保供应商和采购方对验收结果达成一致。



# 🧾 合同与发票流程

## 合同与发票的区别
### 详细说明
- **合同**：用于确认购买意向，卖方同意出售商品或服务，买方同意购买。
- **发票**：卖方开具的账单，用于请求买方付款。
- 合同和发票是两个不同的文件，合同是交易的基础，发票是付款的依据。

## 发票接收与核对流程
### 详细说明
- 买方收到发票后，会在系统（如Docsa）中查看发票内容。
- 核对发票是否正确，防止错误收费。
- 例如：买方拒收了10个商品中的2个，但发票上仍然全部计费，导致多收费。

### 三方匹配（Three-way matching）
- 是一种核对流程，用于确保发票金额与合同和实际收货数量一致。
- 目的是防止错误或欺诈性付款。

| 流程步骤 | 说明                         |
| -------- | ---------------------------- |
| 1. 合同签订 | 买卖双方确认交易条款           |
| 2. 货物交付 | 卖方将商品或服务交付买方       |
| 3. 发票开具 | 卖方根据交付情况开具发票       |
| 4. 发票接收 | 买方收到发票并录入系统         |
| 5. 发票核对 | 买方核对发票与合同及收货情况   |
| 6. 三方匹配 | 确认合同、发票、收货单一致后付款 |

> **重要提示**：核对发票时必须严格执行三方匹配，避免因错误计费导致多付款项。



# 🧾 三方匹配 (Three-Way Matching)

## 定义  
- *三方匹配* 是指核对 **采购订单**、**收货单据** 和 **发票金额** 三者是否一致的过程。  
- 目的是确保所订购的物品、实际收到的物品以及账单金额都正确无误。

## 重要性  
- 防止 **多付** 或 **少付** 费用。  
- 只有三方匹配无误，才能启动付款流程。

## 流程说明  
| 步骤       | 内容说明                             |
|------------|------------------------------------|
| 采购订单   | 确认订购的物品及数量                 |
| 收货单据   | 确认实际收到的物品及数量             |
| 发票金额   | 核对账单金额是否与订单和收货一致     |
| 付款       | 三方匹配无误后，进行付款操作          |

# 💻 ERP系统中的付款流程

## 发票处理  
- 在Docsa及其他ERP系统中，**已批准的发票** 会被转换成 **付款单据**。  
- 不能直接付款的原因是系统需要处理大量交易，避免频繁付款带来的管理混乱。

## 交易量管理  
- 每个月可能有成百上千笔交易。  
- 通过先生成付款单据，再统一处理付款，提高效率和准确性。

> “三方匹配确保付款准确无误，避免多付或少付，同时通过ERP系统的付款单据管理大量交易，提高财务操作效率。”



# 💰 付款批次管理

## 付款批次概述
### 付款批次定义
- *付款批次*指将所有应付款项集中在一个时间点（通常是每月月底）统一支付的流程。
- 这种方式便于统一管理和审批付款。

### 付款批次流程
- 将所有应付款项汇总成一个批次。
- 在指定时间统一进行付款。

## 付款系统集成与操作

| 操作方式       | 说明                                                         |
|--------------|------------------------------------------------------------|
| **系统内支付**   | 通过Docsa集成的支付系统完成，支持连接新加坡本地银行（如UOB、HSBC）及印尼本地银行。 |
| **银行系统审批** | 付款申请可在银行系统内进行审批，确保流程合规。                             |
| **线下支付**     | 现金支付或手动转账等线下方式也可使用，付款信息可手动录入Docsa系统。               |

### 端到端采购付款流程
- 该流程覆盖建筑行业常见的采购付款操作。
- 也适用于其他行业的采购付款管理。

> **总结：** 通过Docsa系统的付款批次管理，实现了采购付款的集中、规范和多渠道支付支持，提升了付款效率和透明度。



# 📝 平台流程的重要性

## 流程的刚性特点
### 细节
- 许多公司流程非常**刚性**
- 具有严格的**指挥链**
- 每一步都需要**审批通过**后才能进入下一步
- 主要原因是处理的交易金额巨大，可能达到**数十万甚至数百万**

## 在平台（如Docsa）中执行流程的优势
### 细节
- 平台覆盖了**整个流程**
- 通过平台可以更好地**管理和展示流程演示**
- 确保每个环节都由**责任方进行审核和确认**
- 提高流程的**透明度和效率**

> “因为他们处理的是可能达到数十万甚至数百万的交易，所以每一步都必须由责任方进行检查。”
