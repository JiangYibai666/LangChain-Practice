# 🛫 机票与酒店预订智能体协作

## 场景描述
- 用户需要一名执行助理，帮忙预订机票和酒店
- 业务需求：用户从新加坡出发，前往上海出差
- 需要预订往返机票及对应时间段的酒店

## 智能体协作需求

| 需求点           | 说明                                                         |
|------------------|--------------------------------------------------------------|
| 出发地           | 新加坡                                                       |
| 目的地           | 上海                                                         |
| 出发日期         | 5月1日                                                       |
| 返回日期         | 5月4日                                                       |
| 酒店入住时间     | 需与抵达上海时间相匹配，入住时间应在抵达后2-3小时内           |
| 酒店退房时间     | 需与返程航班时间匹配，退房当天需乘坐返程航班                   |
| 智能体间信息共享 | 机票和酒店预订智能体需共享日期和时间信息，确保预订时间协调一致 |

## 交互流程示例
- 用户输入：“帮我预订机票和酒店，我5月1日从新加坡飞上海，5月4日返回。”
- 智能体返回多组方案，每组方案包含：
  - 机票选项（4-5个）
  - 酒店选项（对应机票时间的4-5个）
- 用户根据方案选择最合适的组合

> **重点**：智能体之间需要实时沟通，确保机票和酒店预订时间匹配，满足用户行程需求。



# 🛫 航班与酒店组合逻辑

## 组合的合理性  
### 关键点  
- 航班和酒店的组合必须**合理且符合时间顺序**  
- 例如：  
  - 不能在5月1日飞抵上海，但酒店入住时间是4月30日或5月2日  
  - 到达时间和入住时间应匹配，避免时间冲突  

### 时间匹配示例  
| 到达时间       | 合理的入住时间       | 说明                     |
|--------------|------------------|------------------------|
| 5月1日早上7:00 | 5月1日当天早上或之后  | 合理，方便当天入住           |
| 5月1日晚上18:00 | 5月1日晚上或之后      | 合理，但入住时间应晚于到达时间    |
| 5月1日晚上18:00 | 5月1日早上           | 不合理，入住时间早于到达时间       |

## 航班选择的灵活性  
- 以新加坡飞上海为例，每天约有20个航班  
- 可以选择早上7:00或8:00的航班，方便当天入住酒店  
- 需要确保航班时间和酒店入住时间的匹配，提升用户体验
